# Phase 1 Data Model — Phase 6: Drug-Interaction Cooldowns

Phase 6 adds **one new persistent table** (`dose_interaction_overrides`,
the override audit per ADR-0008 / D2) and **no new columns** on
existing tables. Detection itself requires **no schema change** — the
`medication_interactions` table shipped in Phase 1 and `doses` /
`dose_voids` shipped in Phase 4 already carry every fact the detector
reads.

This document records:
1. Existing columns Phase 6 reads.
2. The one new persistent table.
3. The new server-computed value objects (not persisted).
4. The new error type and its wire shape.
5. Detection invariants.

---

## Existing entities Phase 6 reads

### Entity: `MedicationInteraction`

**Table**: `medication_interactions`
(`backend/src/medminder/db/models/medication_interactions.py`) —
**shipped Phase 1; enforcement added here. No migration.**

| Column | Type | Phase 6 use |
|---|---|---|
| `id` | UUID PK | Rule identity (delete by id). |
| `medication_id` | UUID FK → medications.id (RESTRICT, indexed) | One side of the unordered pair. |
| `conflicting_medication_id` | UUID FK → medications.id (RESTRICT, indexed) | Other side; matched in either order. |
| `cooldown_minutes` | int, CHECK `> 0` | Cooldown length. |
| `created_at` | timestamptz | Audit only. |

Invariants already enforced at the DB (Phase 1, not re-checked in
app logic):
- `ix_medication_interactions_pair` UNIQUE on
  `(LEAST(medication_id, conflicting_medication_id),
  GREATEST(...))` → exactly one row per unordered pair.
- `ck_interactions_cooldown_pos` → `cooldown_minutes > 0`.
- `ck_interactions_distinct_pair` → no self-pair.

### Entity: `Dose`

**Table**: `doses` (`backend/src/medminder/db/models/doses.py`) —
**no migration.**

| Column | Type | Phase 6 use |
|---|---|---|
| `id` | UUID PK | Referenced by the new override row. |
| `user_id` | UUID FK | Cross-user isolation (FR-019). |
| `medication_id` | UUID FK | Joins doses to the rule pair. |
| `taken_at` | timestamptz | The single fact the detector reads — the partner's most-recent non-voided `taken_at` arms the cooldown. |

### Entity: `DoseVoid`

**Table**: `dose_voids`
(`backend/src/medminder/db/models/dose_voids.py`) — **no migration.**

Phase 6 reads `dose_id` only: a dose is non-voided iff no
`dose_voids` row references it (Phase 4 / ADR-0005 invariant, reused
via the existing `not_(select(DoseVoid.id).where(...).exists())`
pattern in `create_dose`). Voided doses do not arm a cooldown
(FR-008).

### Entity: `Medication`

**Table**: `medications`
(`backend/src/medminder/db/models/medications.py`) — **no
migration.** Phase 6 reads `id`, `user_id` (isolation), `name`
(conflict display string), `deleted_at` (soft-deleted medications
never appear in any interaction-state response and never warn —
FR-018).

## New persistent entity

### Entity: `DoseInteractionOverride`  *(NEW)*

**Table**: `dose_interaction_overrides`
(`backend/src/medminder/db/models/dose_interaction_overrides.py`).
Append-only audit, mirroring `dose_voids` (ADR-0005). One row per
(dose, conflicting medication) that was in active conflict when the
user explicitly proceeded (D2). Never updated or deleted.

| Column | Type | Constraints | Notes |
|---|---|---|---|
| `id` | UUID PK | `uuid_pk()` | |
| `dose_id` | UUID | FK → `doses.id` `ondelete=RESTRICT`, NOT NULL | The recorded (acknowledged) dose. |
| `conflicting_medication_id` | UUID | FK → `medications.id` `ondelete=RESTRICT`, NOT NULL | A medication in active conflict at acknowledgment time. |
| `created_at` | timestamptz | `created_at_col()` | When the override was recorded. |

`__table_args__`: `UniqueConstraint(dose_id,
conflicting_medication_id, name="uq_dose_interaction_override_pair")`.

**Attribution**: the proceeding user is `doses.user_id` of the
referenced dose (single-tenant; no separate actor column needed —
the dose already attributes the action, consistent with how
`dose_voids` attributes via `voided_by_user_id` for the distinct
voider case).

**Write rule**: inserted in the **same transaction** as the `doses`
row, only when an acknowledged dose clears one or more active
conflicts. No conflict ⇒ no override rows even if
`interaction_acknowledged=true`.

**Migration impact**: ONE Alembic revision (next id `0004`,
`backend/alembic/versions/0004_*.py`), generated by `just
migrate-rev "Phase 6: dose_interaction_overrides"`. The model
declares the table so `alembic check` reports no drift after the
revision is committed.

## New server-computed value objects (not persisted)

In-memory shapes returned by `domain/interactions.py`, converted to
the Pydantic wire model `InteractionStateOut` at the API boundary
(domain stays free of Pydantic).

### `InteractionConflict`

| Field | Type | Notes |
|---|---|---|
| `as_of` | `datetime` (UTC) | The `now` the state was computed at; seeds the client counter. |
| `conflicts` | `list[ConflictItem]` | Every currently-active conflict for the medication (FR-009). Non-empty when this object exists; absence of conflict is represented by the detector returning `None`. |

### `ConflictItem`

| Field | Type | Notes |
|---|---|---|
| `conflicting_medication_id` | `UUID` | The other medication. |
| `conflicting_medication_name` | `str` | Display name (FR-004 / FR-012). |
| `armed_dose_taken_at` | `datetime` (UTC) | The partner's most-recent non-voided `taken_at` that armed this cooldown. |
| `cooldown_elapses_at` | `datetime` (UTC) | `armed_dose_taken_at + cooldown_minutes`. |
| `remaining_seconds` | `int` (≥ 0) | `max(0, int(cooldown_elapses_at - now))` — clamped at zero (boundary is exclusive). |

`InteractionStateOut` is the wire mirror (same fields; UUIDs and
RFC-3339 datetimes); `to_interaction_state_out` adapter in
`api/schemas/timers.py` (or a new `api/schemas/interactions.py`)
performs the conversion, sibling to `to_timer_state_out`.

## New error type

### `MedicationInteractionConflict` (domain exception)

Defined in `domain/doses.py`, **alongside** the existing `DoseError`
hierarchy, as a `DoseError` subclass (ADR-0008). It is intentionally
*not* placed in `domain/interactions.py`: `doses.py` imports the pure
detector from `interactions.py` (one-directional, mirroring how
`doses.py` imports `multi_sub_dose_window_full` from `timers.py`), so
defining the exception in `interactions.py` while subclassing
`DoseError` would create a circular import. `interactions.py` stays
free of any `doses` import. Plain Python, no Pydantic.

| Attribute | Type | Notes |
|---|---|---|
| `medication_id` | `UUID` | The medication whose dose was attempted. |
| `conflict` | `InteractionConflict` | Full payload (all active conflicts). |

Raised inside `create_dose()` when a conflict is detected and
`interaction_acknowledged` is false.

### `InteractionCooldownViolation` (wire-format model)

Pydantic model in `backend/src/medminder/api/schemas/errors.py`,
sibling to `MinIntervalViolation` / `WindowFullViolation`.

| Field | Type | Notes |
|---|---|---|
| `code` | `Literal["interaction_cooldown_active"]` | Stable identifier, distinct from Phase 5 codes (FR-004 / FR-010). |
| `medication_id` | `UUID` | The blocked medication. |
| `conflicts` | `list[ConflictOut]` | Each: `conflicting_medication_id`, `conflicting_medication_name`, `cooldown_elapses_at`, `remaining_seconds` (≥ 0). |
| `cooldown_elapses_at` | `datetime` (UTC) | Latest-ending active conflict (drives the single headline time). |
| `remaining_seconds` | `int` (≥ 0) | For the latest-ending conflict. |

The `app.py` exception handler returns this body with HTTP **409
Conflict** when `MedicationInteractionConflict` is raised.

## Detection invariants

D1 in `research.md` carries the rationale; restated for quick
reference and direct testing in `tests/domain/test_interactions.py`:

1. A rule arms a cooldown only **after** one medication of the pair
   has a non-voided dose; the medication taken first never warns
   (FR-007).
2. The arming dose is the partner medication's **most-recent
   non-voided** dose. Voided doses never arm (FR-008).
3. A conflict is active iff `now < armed_dose_taken_at +
   cooldown_minutes`. At exactly `armed_dose_taken_at + cooldown`
   the conflict is **not** active (`remaining_seconds` clamped at 0;
   boundary exclusive — consistent with Phase 5).
4. Symmetric: a single row matches in either order
   (`LEAST/GREATEST`); no direction-specific storage (FR-006).
5. Multi-conflict: every active conflicting medication appears in
   `conflicts`; the headline `remaining_seconds` /
   `cooldown_elapses_at` reflect the **latest-ending** cooldown
   (FR-009 / US2.6). A single acknowledgment covers recording the
   dose; one `dose_interaction_overrides` row is written per active
   conflict.
6. Soft-deleted medications (either side) produce no conflict and no
   interaction-state surface (FR-018).
7. All arithmetic is UTC; user-facing strings honour the user's
   `timezone` (DST-safe, clock-skew-safe — server-authoritative).
